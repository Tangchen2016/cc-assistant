# 邮件辅助

只辅助本人收取验证码或登录链接、查看和复制 / 在独立浏览器打开；不提交注册、登录、验证码或条款，不连接 iCloud 收件箱。

## 数据流程

- 用户在注册页填邮箱，点击「等待登录邮件」。鉴权 Worker 创建 10 分钟等待窗口。
- Cloudflare 的 Email Routing 将邮件交给 cc-mail-assistant。Worker 首先向原有已验证的 iCloud 地址转发，再尝试解析。
- 只处理当前域名、正在等待的收件地址，且发件人地址属于 Claude / Anthropic 域名的邮件。发件人筛选不是身份认证保证，界面始终由用户核对；邮件内容不执行、不打开链接。
- 提取带验证码上下文的 4–8 位数字，或唯一的 HTTPS claude.ai/magic-link 登录链接；链接携带的邮箱必须与当前收件人一致。客户端再次校验域名、路径和邮箱后，仅在用户点击时打开当前独立浏览器。不同候选或不支持的格式提示去 iCloud 查看。
- 不存正文或附件，不记录邮箱 / 验证码 / 密钥日志。提取大小上限 512 KiB；超限仍先转发。
- 邮件结果与等待记录使用 Workers KV，最长 10 分钟；停止后客户端立即清除，并请求删除服务端会话和结果。KV 是最终一致性，跨地区可能延迟，不能保证即时到达或即时物理删除；过期判断拒绝旧会话。
- 客户端每 10 秒查询，改邮箱、关闭弹窗或停止即取消；验证码仅内存显示，复制到系统剪贴板由用户主动触发。

## 配置与部署

独立目录 `cloud/mail-assistant` 使用 cf CLI 和 typed cloudflare.config.ts。安装依赖后执行 `npm run check`、`npm test`、`npx cf build`。部署前先进行 CLI 授权。

部署使用单独 KV 和 API_KEY secret。访问密钥必须随机生成至少 32 字符，不可放在公开 App 包、仓库、URL 或日志。此版本是本人私有服务，不是多租户公开接码 API；持有访问密钥的人能为该域名开启等待。

App 的连接配置保存在 `Subscription Studio/private-mail/settings.json`，目录 0700、文件 0600、排除系统备份，不进钥匙串或号池 JSON。它是本机文件权限保护，不是加密存储。

先验证 Worker 的鉴权和转发，再把收信规则改为 Worker。改路由后仍必须用实际来信核对 iCloud 收件和 App 提取，两者均成功才算端到端验收。回退：把全收规则改回原 iCloud 转发目标。

## 独立浏览器内的本地邮件页

注册页的「在账号浏览器打开邮件页」会打开一个只监听 127.0.0.1 的临时页面。未开始等待时会先启动当前邮箱的 10 分钟等待窗口，再打开该账号对应的独立浏览器。网页通过随机路径读取本机内存里的结果，不持有 Worker 访问密钥，也不请求 iCloud。

点击官方登录链接使用当前标签页导航，保留该浏览器的账号环境。页面设置 no-referrer、禁止嵌入、同源读取和不缓存；服务器验证 Host / Origin / Sec-Fetch-Site。关闭注册弹窗、切换邮箱或停止后旧页面失效。这个入口不能保证官网接受登录，不能绕过人机验证。
