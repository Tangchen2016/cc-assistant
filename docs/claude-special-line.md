# Claude 专线：透明接管原型

状态：未启用、未安装系统扩展、未改变系统代理或 VPN。菜单和策略单测不是全机接管验收。

## 数据路径

原有浏览器 / 终端 → macOS 透明代理扩展 → 已识别 Claude 连接 → 内置引擎 → 前置节点 → 静态出口。
其他连接由透明代理返回 false，交还操作系统；不能简单重建为 DIRECT 连接。

## 保护契约

- 不解密 HTTPS，不记录 URL 参数、Cookie、聊天内容或代理凭据。
- Claude 域名按后缀边界匹配，包含 anthropic.com、claude.ai、claude.com 及子域。第三方身份认证 / 挑战域名不等同于 Claude，覆盖待实测。
- 本地引擎进程存在不代表保护生效。启用需验证系统扩展运行、指定链路就绪及同链路出口。
- 出口证明绑定线路 ID 和引擎世代，最多 30 秒；切换节点、引擎重启、网络变更立即撤销。
- 未核验、探测失败、IP 不符、过期均拒绝已识别 Claude 新连接。UDP 未有受验收链路前拒绝，不能放行 QUIC 绕过。
- 后续运行时必须在撤销时关闭全部已接管活动连接，并去重提示具体原因；不能只阻止新连接。
- 无主机名 / IP-only / 第三方已加密代理连接属于未分类，不能标成已保护。不能据共享 CDN IP 扩大阻断范围。
- 抽样探测只能证明探测时刻的出口；连续保护依赖转发路径约束，不能声称逐个 HTTPS 请求出口均被服务端验证。
- 扩展停止或崩溃可能使系统恢复原路径；在独立故障保护尚未验证前，禁止宣称进程崩溃仍能 fail-closed。

- desktop/special-line/TransparentProxyProvider.swift：拒绝启动的安全原型，未嵌入发行包。

## 必须完成的集成

1. 配置 Apple 团队的 Network Extension entitlement、描述文件、扩展 target 和宿主激活；用实际签名验证系统加载。
2. 使用隔离 loopback 监听器的内置引擎，最小规则仅含前置与静态出口；禁止加载原订阅的任意脚本 / 默认回退策略。
3. 实现 TCP 双向转发、背压、半关闭、超时、取消；避免自身连接重入。凭据不写日志。
4. 实现宿主与扩展的认证 IPC、真实状态、受限事件队列，探测权限不能成为绕过入口。
5. 实现同链路探测与租约更新（运行时用单调时钟），活动连接撤销、网络变化处理及通知。
6. 验收普通浏览器、现有 Bash/Zsh、Claude Code；已有 VPN 的关闭 / 系统代理 / TUN / 强制隧道模式分别测试，包含 IPv4/IPv6、QUIC、DoH、共享 CDN、隧道重连、引擎崩溃。
7. 系统代理若使目标隐藏在第三方代理连接中，报告覆盖不足；未通过的组合禁止显示全机已保护。

## 发行限制

当前只有 Apple Development 身份。证书存在不能证明有对应 entitlement / provisioning，更不等于 Developer ID 公证发行。
不自动停用现有 VPN，不安装根证书，不改用户路由；实际接管需系统扩展授权及兼容性验收。
iOS 需要独立设计与签名验证，不直接复用 macOS 的透明代理方案。
